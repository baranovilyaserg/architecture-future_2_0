## Детальный расчет по этапам

### Текущее состояние (2026)
- **Инфраструктура**: SQL Server лицензии (2.5M) + DC (1.8M) + Power BI (1.2M) + ремонт = 7.2M
- **Разработка**: DWH customization (2M) + ESB Camel (1.2M) + support bugs (1.3M) = 4.5M
- **Персонал**: 8 DBA + 6 ESB интеграторов + 10 BI аналитиков = 3.2M
- **Support**: Vendor contracts + training = 1.1M
- **Compliance**: Аудит + basic security = 0.5M
- **Всего**: 16.5M/год

### Год 1: пилот + гибридный режим
- Запускаем Kafka + Snowflake + PostgreSQL Event Store (AWS)
- Camel и DWH остаются, но упрощаются (read-only)
- 2-3 новых Data Engineer на Event-Driven
- Затраты дублируются, но начинаем экономить на лицензиях
- **Всего**: 16.3M (почти flat)

### Год 2: масштабирование
- Миграция 4+ доменов на Event-Driven
- SQL Server 2008 — отключаем, экономим лицензии
- Персонал: переподготовка интеграторов в Data Engineers
- **Всего**: 11.7M (-28% YoY)

### Год 3: полная миграция
- Деком Camel, SQL Server, Power BI (legacy)
- 100% на Kafka + Snowflake + PostgreSQL
- Data Mesh products в каждом домене
- **Всего**: 9.8M (-16% YoY, -40% CAGR)

## Скрытые выигрыши (не показаны в таблице)

| Выигрыш | Влияние |
|--------|--------|
| Скорость выхода на рынок: 2-3 мес → 1-2 недели | Новые продукты быстрее, конкурентное преимущество |
| Масштабируемость: 1k → 1M events/sec | Мощность для роста без новых инфра-инвестиций |
| Свежесть данных: 3+ часа → <1 сек | Лучшее принятие решений, обнаружение мошенничества |
| Сокращение багов: сложность DWH -60% | Меньше критических инцидентов, выше uptime |
| Облачная гибкость | Multi-region за недели, не месяцы |
